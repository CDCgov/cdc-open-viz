# DEV-13957 — Multiselect All without expanded data

## Ticket-ready explanation

The fix adds an explicit **Show All Option** setting to dashboard data filters using the Multi-select style. Selecting All leaves that category unrestricted, so authors no longer need duplicated All rows or hidden Master columns. Selecting a specific value replaces All; selecting All replaces specific values. Removing the final selection remains an incomplete selection and does not mean All.

Existing filters retain literal value matching unless the new option is enabled. This preserves dashboards whose source data contains a real value named All. Reset/placeholder text does not enable show-all behavior.

## Test fixture and setup

1. Import `packages/dashboard/examples/dashboard-multiselect-show-all.json` into the dashboard editor on a build containing this fix. This is the corrected version of the attached complex-table example.
2. Confirm the dataset has **293 records**, with `Tox Profile`, `Year Published`, `Substance`, `CAS RN`, and `Num` columns. It has no Master columns and no duplicated All rows. The rendered table initially contains 293 records.
3. Confirm all four shared filters use **Data Filter**, **Multi-select**, and **Show All Option**, with default value All. Their column mappings are `Tox Profile` → `Tox Profile`, `Year Published` → `Year Published`, `Substance` → `Substance`, and `CAS RN` → `CAS RN`.
4. The fixture uses **Filter Change** behavior, so results update immediately. Start with All selected in all four filters.

Do not use the expanded 4,688-row attachment as the acceptance fixture: it works around the original bug. Simply deleting Master columns from an old configuration is insufficient; the filters must also target the actual remaining columns and enable Show All Option.

## Selection-limit check

Set Select Limit to 1 for Tox Profile. Starting at All, select Acetone: expect the All chip to be replaced and one Acetone record. Select All again: expect all 293 records. Replacing All must work even though one item already fills the limit. Restore the default limit before repeating the main sequence.

## Compatibility check

Use a separate small dataset containing actual literal values:

```csv
Category,Value
All,10
Acetone,20
```

Create a dashboard table with a Multi-select Data Filter targeting Category. Leave **Show All Option off**, and select the source value All. Expect only the `All,10` record, not both records. Export and reload; the behavior must remain unchanged. Changing reset/placeholder text to All must not enable show-all behavior.
